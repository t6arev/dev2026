## P0. HTTP-коды

### Проблема
Pixel: «код ответа некоторых URL отличен от 200».

### Подтвердилась / не подтвердилась
**Частично подтвердилась — только для URL без trailing slash.**

| URL-форма | Статус | Location |
|-----------|--------|----------|
| `/services/telegram-bots/` и все canonical `/services/*/`, `/cases/*/` | **200** | — |
| `/services/telegram-bots` (без `/`) и все slashless | **301** | → вариант **со** slash |
| `http://…` | **301** | → `https://…` |
| `https://www.dev2026.ru/...` | **301** | → `https://dev2026.ru/...` |
| 404 / 5xx / 302 / 307 / 308 | **не обнаружены** | — |

Browser / YandexBot / Googlebot: **одинаковые статусы** (расхождений нет).

### Причина
GitHub Pages нормализует директории: **trailing slash = канон**. Sitemap и внутренние ссылки уже со slash. Pixel, скорее всего, дергает slashless URL → видит 301 ≠ 200.

### Влияние на SEO
**Низкое / норма.** 301 на канон — правильное поведение, не ошибка индексации. В sitemap каноны с `/`.

### Как исправлено
**Не исправлялось** (ломать trailing-slash redirect нельзя).  
Проверено: внутренних slashless-ссылок на prod HTML нет (`slashless=0`).

## P0. Время ответа сервера (> 200 мс)

### Проблема
Pixel: «время ответа превышает 200 мс».

### Подтвердилась / не подтвердилась
**Не подтвердилась как системная проблема.**

Замеры с локальной точки (RU), curl / urllib:

| Метрика | Значение |
|---------|----------|
| DNS | ~0.5–6 мс |
| TLS | ~32–48 мс, **TLSv1.3** |
| TTFB `/services/telegram-bots/` | **~55–165 мс** (типично ~55–70 после прогрева) |
| Полный GET HTML (gzip) | **~47–70 мс** |
| Холодный 1-й запрос (identity) | ~150–190 мс |

Иногда единичный запрос **≈150–190 мс** — на границе порога Pixel или чуть ниже. Стабильно **> 700 мс TTFB не наблюдается**.

### Причина задержек
- Хостинг: **GitHub Pages** (`Server: GitHub.com`)
- CDN: **Fastly** (`X-Served-By: cache-bma-…`, `X-Cache: HIT/MISS`), **не Cloudflare** (`CF-Ray` отсутствует)
- HTML кэш: `Cache-Control: max-age=600`, есть `ETag`, `Last-Modified`, `Age`
- Сжатие: **gzip** (`Content-Encoding: gzip`) — OK
- Keep-alive / HTTP: curl видит **HTTP/1.1** к edge; дальнейшее ускорение ограничено GHP/Fastly

### Влияние на SEO
**Низкое.** Пороги Pixel (200 мс) жёсткие для shared CDN. Реальное время ответа HTML у сайта в норме для статики.

### Как исправлено
**Не исправлялось** — нет подтверждённого бага приложения.  
Ускорить TTFB «кодом сайта» нельзя (нет серверного приложения). Опция на будущее: Cloudflare перед GHP (не сейчас).

## P0. Время загрузки HTML (> 700 мс)

### Проблема
Pixel: «полная загрузка HTML превышает 700 мс».

### Подтвердилась / не подтвердилась
**Не подтвердилась.**

Размеры HTML (identity / gzip approx):

| Страница | Raw bytes | Gzip ~ | Полный download |
|----------|-----------|--------|-----------------|
| `/` | ~35 KB | ~8 KB | **~46–55 мс** |
| `/services/telegram-bots/` | ~12 KB | ~3 KB | **~49–70 мс** |
| `/cases/ai-bot-telegram/` | ~25 KB | ~6 KB | **~47–71 мс** |

Далеко от 700 мс. Лишних redirect на канонических URL нет (один hop только для slashless / http / www).

### Причина (почему Pixel мог ругаться)
Другая локация зонда, холодный edge, или включение redirect-цепочки / DNS в «время загрузки».

### Влияние на SEO
**Нет** (при наших замерах).

### Как исправлено
**Не требуется.**

## Доп. находка (не из Pixel) — пустой canonical

### Проблема
На prod HTML всех `/services/*/`:

```html
<link rel="canonical" href="">
```

Заполняется только JS (`service-page.js`). Без JS canonical пустой.

### Влияние на SEO
**Среднее.** Роботы без полного JS могут получить плохой/пустой canonical.

### Как исправлено (в репо, ждать деплоя)
Проставлены статические canonical URL в:

- `services/telegram-bots/index.html`
- `services/telegram-bots/ai-bots/index.html`
- `services/ai-implementation/index.html`
- `services/ai-assistants/index.html`
- `services/ai-agents/index.html`
- `services/web-development/index.html`
- `services/_template.html`

**На prod пока ещё пустые** — нужен отдельный тех. деплой (не UI polish целиком).
