# Отчёт: новые URL vs пересечение интентов

> Ветка docs: часть `seo/p1-new-pages-arch`  
> **Не публиковать** страницы без согласования  
> Дата: 2026-07-15

---

## Кандидаты

| URL | Черновой интент |
|-----|-----------------|
| `/services/telegram-mini-apps/` | Mini Apps как продукт/интерфейс внутри Telegram |
| `/services/custom-development/` | Кастомные цифровые продукты «под задачу» |
| `/services/saas-development/` | Продуктовая разработка SaaS (подписка, биллинг, мультитенант) |

Приоритет согласования: Mini Apps → custom → SaaS.

---

## Пересечение с `/services/web-development/`

Текущая web-страница уже тянет: сайты, веб-сервисы, ЛК, API, CRM, (после rewrite) SaaS.

| Если создать… | Риск каннибализации |
|---------------|---------------------|
| `custom-development` + оставить `web-development` как «сайты» | Средний: «кастом» перекроет сервисы/ЛК |
| `saas-development` рядом с web | Высокий, если web тоже тащит SaaS |
| Только Mini Apps | Низкий относительно web; лёгкий overlap с telegram-bots |

---

## Вариант A — кластер custom

```
/services/custom-development/          ← хаб «кастом под задачу»
  /services/custom-development/saas/
  /services/custom-development/web-services/
```

- `web-development` → редирект/слияние в custom или сужение до «лендинги/витрины»  
- Плюс: один продуктовый кластер  
- Минус: больше URL, сильнее ломка текущей структуры

## Вариант B — развод web / SaaS (рекомендация)

| URL | Интент |
|-----|--------|
| `/services/web-development/` | Сайты, лендинги, корпоративные витрины, простые веб-сервисы, доработки |
| `/services/saas-development/` | Подписочный продукт: биллинг, роли, тенанты, ЛК продукта, рост |
| `/services/telegram-mini-apps/` | Mini App как UX-слой Telegram (каталоги, кабинеты в TG) |
| custom | **не создавать отдельный URL**: кастом = способ работы на всех страницах («я проектирую под задачу»), не отдельный интент |

### Почему B лучше для текущего сайта
1. Меньше каннибализации с уже живым `web-development`.  
2. SaaS — отдельный коммерческий интент (стартап/продукт), web — «нужен сайт/сервис».  
3. «Кастом» как SEO-хаб размыт и пересекается со всем (как сейчас ai-assistants).  
4. Согласуется с позиционированием соло-разработчика: меньше страниц-дублей.  
5. Урок аудита кейсов: лучше меньше сильных URL с crawlable текстом, чем тонкий хаб.

---

## Рекомендация

**Принять вариант B (предварительно).**  
Финально — только после согласования владельцем.

Порядок появления после ревью:

1. `/services/telegram-mini-apps/` (закрывает пробел telegram-bots ↔ продукт)  
2. `/services/saas-development/` (забирает SaaS с web и assistants)  
3. Не создавать `/services/custom-development/` без новой семантики
