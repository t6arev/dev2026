## Корневая идея внедрения (лучше, чем «только правки JS»)

Сейчас (факт):

| Поле | В HTML до JS | После JS |
|------|--------------|----------|
| `<title>` | `Услуга — dev2026.ru` на всех 6 URL | из `services-data.js` |
| `meta description` | пустой | из JS |
| OG / Twitter | нет | нет |
| `H1` | пустой `#serviceHeroTitle` | из JS |
| Body-секции | пустые контейнеры | из JS |
| `canonical` | уже проставлен (`72dc19a`) | JS дублирует |

Яндекс/часть краулеров видит шаблон → дубликат Title. Как в аудите кейсов с JS-портфолио.

**Рекомендуемый подход:**

1. **P0 meta/H1 shell** — зашить Title, Description, OG, Twitter, H1(+lead) и короткий crawlable абзац в каждый `services/*/index.html`.
2. **Контент-ветки** — переписать `js/services-data.js` + зеркалить ключевые блоки в HTML (или `noscript` + видимый static fallback), чтобы интенты были и для ботов, и для UI.
3. Скрипт синхронизации (опционально позже): `scripts/sync_service_shell.py` — data → HTML meta/H1, чтобы не разъезжалось.
4. **Не публиковать** текстовые ветки без ревью владельца.

## Общие правила контента (все ветки 1–6)

- Первое лицо: я / разрабатываю / внедряю  
- Запрет: мы, команда, агентство, студия  
- Нет фикс. цен и сроков; вариативные нейтральные формулировки  
- Не все ключи из выгрузки; без мусорных (купить бота, MAX, нейро-курсы…)  
- Каркас: H1 → экран → для кого → решения → (2 сценария если уместно) → возможности → этапы → кейсы → FAQ → CTA  
- `ai-implementation`: **без** искусственного «стартап-сценария»
