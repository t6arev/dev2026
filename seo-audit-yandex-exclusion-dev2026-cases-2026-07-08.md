* На главной ссылки на кейсы есть, но **вставляются JS-рендером** (в HTML source они не присутствуют).
* Поэтому вероятность “слабого внутреннего PageRank” у этих URL — высокая.

#### Schema.org / breadcrumbs
* Встроены: `BreadcrumbList` + `CreativeWork` + `FAQPage` (Question/Answer).

## Шаг 3 (максимально вероятные причины решения Яндекса “мало шансов”)

> Важно: ниже — не “перечень возможных причин”, а наиболее вероятные три, которые лучше всего подтверждаются фактами из сайта.

## 1) Недостаточный внутренний PageRank / “изолированность” кейсов из-за JS-only перелинковки и отсутствия live-кластера услуг
**Доказательства:**
* В исходном HTML главной страницы список кейсов не содержит ссылок (контейнер пуст): `#portfolioGrid` — пустой.
* Ссылки на кейсы создаются через JS по данным `window.caseData` (порядок: на `DOMContentLoaded`), т.е. для поискового робота, который не до конца/не сразу выполняет JS, эти кейсы получают меньше ссылочного веса.

```123:136:index.html
<div class="portfolio-accordion" id="portfolioGrid"></div>
```

```86:161:js/main.js
const pageLinkHtml = hasPage
    ? `<a href="${page.url}" class="case-page-link primary-btn">Подробнее о проекте</a>`
    : '';
```

* Параллельно **кластер услуг и блог на live-домене отсутствуют (404)**, поэтому кейсы не получают “естественные” контекстные ссылки из тематически близких посадочных.

## 2) Контент кейсов в текущем виде воспринимается как “недостаточно доказательный” (thin/boilerplate без KPI)
**Доказательства:**
* У всех 4 исключённых страниц **короткий текстовый объём**: `<p>` ~ **13–16** и FAQ **5–6** вопросов.
* В блоках “Решение/Результат” используется обобщённая формулировка без измеримых эффектов (нет процентов, нет конкретных численных KPI результата в “результате/последствиях” — только “ускорить/снизить/масштабируется”).

## 4) Что нужно исправить срочно (высокий приоритет)

### 4.1 Сделать ссылки на кейсы “видимыми” поисковым роботам без ожидания JS
**Почему срочно:** это влияет на внутренний PageRank и скорость повторной переоценки страницы.

Конкретно:
* В HTML source главной страницы добавить предрендер (хотя бы ссылки) для кейсов (SSR-подход либо статический markup).
* Альтернатива: `<noscript>` с полным списком `a href="/cases/{slug}/"` для всех кейсов из `window.caseOrder`.

### 4.2 Выложить live-кластеры услуг (и включить ссылочный модуль “кейсы доказательство” на эти URL)
**Почему срочно:** на live домене сейчас `/services/*` = 404, значит кейсы не получают кластерных ссылок.

Конкретно (уже готово в текущем проекте, судя по `services-data.js`):
* Для кластера Telegram-ботов в `relatedCaseIds` включены `bot2` и `bot7`:

```143:149:js/services-data.js
cases: { kicker: 'КЕЙСЫ', title: 'Реализованные проекты' },
relatedCaseIds: ['bot2', 'bot4', 'bot7'],
faqBlock: { kicker: 'ВОПРОСЫ И ОТВЕТЫ', title: 'FAQ' },
```

* Для AI-агентов включён `site4`:

```489:490:js/services-data.js
relatedCaseIds: ['site4'],
faq: [],
```

* Для блоков с AI-assistants включён `bot6`.

* Механика получения URL кейса подготовлена:
```602:606:js/services-data.js
getCaseUrl: function (caseId) {
    ...
    return '/cases/' + data.page.slug + '/';
},
```

После релиза этих страниц у кейсов появятся реальные контекстные ссылки с тематических посадочных.

### 4.3 Обновить подачу “Результата” и “Доказательности” на исключённых кейсах
**Почему срочно:** даже при росте PR-ссылок Яндекс может держать страницы вне поиска, если они выглядят как “шаблонная история без KPI”.

Конкретные изменения:
* Добавить в “Результат” измеримые показатели (точность/скорость/экономия/конверсия/нагрузка до-после).
* Добавить 2–3 конкретных артефакта внедрения (скрин админки/дашборда, фрагмент архитектурной схемы, список модулей/эндпоинтов, примеры промптов).
* Устранить trust-неспецифичность:
  * `/cases/ai-bot-telegram/`: заменить hero-коллаж/og-image на кейс-специфичный визуал.
  * `/cases/ai-assistant-business/`: привести hero-коллаж в соответствие OG-image/смыслу кейса.

## 6) Что изменится после публикации новых SEO-страниц
1) Роботам и алгоритмам Яндекса станет проще видеть внутренний граф ссылок между услугами → кейсами.
