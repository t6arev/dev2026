# SEO-кластерная архитектура услуг

> Зафиксировано 2026-07-03. Стратегический перелом: **кейс → SEO** заменён на **кластер → услуга → дочерние страницы → кейсы как доказательство**.  
> **P0-реализация перелинковки:** [`09-p0-case-reindex.md`](09-p0-case-reindex.md)

---

## Принцип

Каждая новая страница усиливает родительскую. Родительская распределяет внутренний вес между дочерними. Поисковики любят связанные кластеры больше, чем набор несвязанных URL.

---

## Уровни (LEVEL)

| Level | Роль | Пример |
|-------|------|--------|
| 1 | Hub / overview | Главная → блок «Услуги» |
| 2 | Кластер-услуга | `/services/telegram-bots/` |
| 3 | Коммерческие посадочные | AI-боты, Mini Apps, CRM-боты |
| 4 | Нишевые long-tail | Бот для магазина, доставки, салона |

---

## Порядок блоков на странице услуги (путь принятия решения)

```
Описание
  ↓
Кому подойдёт (аудитория)          ← задел под LEVEL-4 страницы
  ↓
Какие задачи решает                ← «у меня проблема»
  ↓
Какие решения разрабатываем        ← «каким способом»
  ↓
Этапы разработки                   ← «как это происходит», вертикальный timeline + scroll
  ↓
Реализованные проекты              ← доказательство
  ↓
FAQ (в т.ч. стоимость)             ← «сколько стоит»
  ↓
Форма / CTA                        ← заявка
```

**Убрано с UI:** отдельный блок «Технологический стек». Ключи стека остаются в SEO-тексте, FAQ и schema — не отдельной секцией.

## Связь с кодом

| Концепт | Где в коде |
|---------|------------|
| Контент услуги | `js/services-data.js` → `audience`, `problems`, `tasks`, `steps` |
| Порядок секций | `services/_template.html` |
| Рендер | `js/service-page.js` |
| Scroll-timeline этапов | `js/motion.js` → `bindServiceProcessScrollSteps` |
| Стили | `css/services.css` |

*Не делать сразу 20 страниц. Сначала эталон → ТОП-3 → остальные по кластеру.*
